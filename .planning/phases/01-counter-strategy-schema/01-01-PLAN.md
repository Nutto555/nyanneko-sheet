Create `supabase/migrations/007_counter_strategies.sql` with exactly the following content (verified against all existing migration patterns in 001–006):

**Section 1 — enemy_defense_templates** (per D-01, D-02, DATA-02):
- UUID PK with gen_random_uuid() (established pattern)
- name_en VARCHAR(200) NOT NULL — English display name required
- name_th VARCHAR(200) — Thai translation nullable (matches bilingual pattern in characters, equipment)
- slug VARCHAR(200) UNIQUE NOT NULL — URL-friendly ID (same as all other entities)
- description TEXT — optional prose
- is_featured BOOLEAN DEFAULT FALSE — supports LOOK-06 (featured templates gallery, Phase 4) without future schema change
- sort_order INT DEFAULT 0 — admin-controlled display order for Phase 4/6
- created_at TIMESTAMPTZ DEFAULT NOW()
- updated_at TIMESTAMPTZ DEFAULT NOW()

**Section 2 — enemy_defense_members** (per D-01, D-02, DATA-02):
- UUID PK
- template_id UUID NOT NULL REFERENCES enemy_defense_templates(id) ON DELETE CASCADE
- character_id UUID NOT NULL REFERENCES characters(id) ON DELETE CASCADE
- position INT DEFAULT 0 — slot ordering within the template
- created_at TIMESTAMPTZ DEFAULT NOW()
- UNIQUE(template_id, character_id) — a character appears at most once per template
- NO updated_at — this is an append-only join table; update = delete + reinsert

**Section 3 — counter_strategies** (per D-01, D-03, D-06, DATA-01, DATA-03, DATA-05):
- UUID PK
- template_id UUID NOT NULL REFERENCES enemy_defense_templates(id) ON DELETE CASCADE
- counter_team_id UUID REFERENCES team_compositions(id) ON DELETE SET NULL — NULLABLE (strategy can be a stub before team is assigned; per RESEARCH.md Pitfall 4)
- priority INT NOT NULL DEFAULT 0 — per D-06; explicit integer, lower = try first
- condition_note TEXT — human-readable summary of when this strategy applies (e.g., "Use when enemy has Lubu but not Elena")
- strategy_notes TEXT — free text explanation; TEXT not JSONB (per RESEARCH.md discretion decision, DATA-05)
- is_active BOOLEAN DEFAULT TRUE — soft disable without data loss
- created_at TIMESTAMPTZ DEFAULT NOW()
- updated_at TIMESTAMPTZ DEFAULT NOW()
- CONSTRAINT chk_counter_priority CHECK (priority >= 0)

**Section 4 — strategy_conditions** (per D-01, D-04, D-05, DATA-01, DATA-04):
- UUID PK
- strategy_id UUID NOT NULL REFERENCES counter_strategies(id) ON DELETE CASCADE
- character_id UUID NOT NULL REFERENCES characters(id) ON DELETE CASCADE — conditions reference the ENEMY TEAM characters (per D-05)
- condition_type VARCHAR(50) NOT NULL
- created_at TIMESTAMPTZ DEFAULT NOW()
- CONSTRAINT chk_condition_type CHECK (condition_type IN ('must_have', 'must_not_have')) — per D-04; enforces controlled vocabulary at DB level
- UNIQUE(strategy_id, character_id, condition_type) — prevents duplicate predicates for the same character in the same direction
- NO updated_at — conditions are replaced wholesale (delete all + reinsert), not individually edited

**Section 5 — updated_at triggers** (reuse existing function from 004; DO NOT recreate the function):
```sql
CREATE TRIGGER trg_enemy_defense_templates_updated_at
  BEFORE UPDATE ON enemy_defense_templates
  FOR EACH ROW EXECUTE FUNCTION set_updated_at();

CREATE TRIGGER trg_counter_strategies_updated_at
  BEFORE UPDATE ON counter_strategies
  FOR EACH ROW EXECUTE FUNCTION set_updated_at();
```
Only enemy_defense_templates and counter_strategies get triggers — enemy_defense_members and strategy_conditions are append-only join tables (no updated_at column).

**Section 6 — Indexes** (per RESEARCH.md index strategy, verified against 001_initial_schema.sql pattern):
```sql
CREATE INDEX idx_enemy_defense_members_template  ON enemy_defense_members(template_id);
CREATE INDEX idx_enemy_defense_members_character ON enemy_defense_members(character_id);
CREATE INDEX idx_counter_strategies_template     ON counter_strategies(template_id);
CREATE INDEX idx_counter_strategies_template_priority ON counter_strategies(template_id, priority);
CREATE INDEX idx_strategy_conditions_strategy    ON strategy_conditions(strategy_id);
CREATE INDEX idx_strategy_conditions_character   ON strategy_conditions(character_id);
```
The composite index (template_id, priority) serves the primary query: load all active strategies for template X ordered by priority — avoids separate sort step.

**Section 7 — RLS policies** (per D-07, open read/write pattern from 006_open_writes.sql):
```sql
ALTER TABLE enemy_defense_templates ENABLE ROW LEVEL SECURITY;
ALTER TABLE enemy_defense_members   ENABLE ROW LEVEL SECURITY;
ALTER TABLE counter_strategies      ENABLE ROW LEVEL SECURITY;
ALTER TABLE strategy_conditions     ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Public read enemy_defense_templates" ON enemy_defense_templates FOR SELECT USING (true);
CREATE POLICY "Public read enemy_defense_members"   ON enemy_defense_members   FOR SELECT USING (true);
CREATE POLICY "Public read counter_strategies"      ON counter_strategies      FOR SELECT USING (true);
CREATE POLICY "Public read strategy_conditions"     ON strategy_conditions     FOR SELECT USING (true);

CREATE POLICY "Anon write enemy_defense_templates" ON enemy_defense_templates FOR ALL TO anon USING (true) WITH CHECK (true);
CREATE POLICY "Anon write enemy_defense_members"   ON enemy_defense_members   FOR ALL TO anon USING (true) WITH CHECK (true);
CREATE POLICY "Anon write counter_strategies"      ON counter_strategies      FOR ALL TO anon USING (true) WITH CHECK (true);
CREATE POLICY "Anon write strategy_conditions"     ON strategy_conditions     FOR ALL TO anon USING (true) WITH CHECK (true);
```
Open write is intentional per D-07. Structure is ready for tightening in v2 when AUTH-01 ships.

**Critical: DO NOT** add `CREATE FUNCTION set_updated_at()` — it already exists from migration 004 and will cause "function already exists" error (RESEARCH.md Pitfall 3).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Migration file → Database | SQL DDL applied by admin/CLI; not user-accessible at runtime |
| anon client → new tables | After migration, anon Supabase key can read and write all four tables (open RLS per D-07) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | strategy_conditions.condition_type | mitigate | CHECK constraint `(condition_type IN ('must_have', 'must_not_have'))` enforces at DB level; invalid values rejected regardless of application code path |
| T-01-02 | Tampering | counter_strategies.priority | mitigate | CHECK constraint `(priority >= 0)` prevents negative priority values; NOT NULL prevents null injection |
| T-01-03 | Tampering | Anon writes to all four tables | accept | Open write is intentional per D-07 for internal guild tool; tightening deferred to v2 AUTH-01; risk is acceptable at current scale |
| T-01-04 | Tampering | FK integrity (enemy_defense_members, strategy_conditions) | mitigate | NOT NULL on FK columns + ON DELETE CASCADE ensures referential integrity is DB-enforced, not application-enforced |
| T-01-05 | Tampering | Migration file contents | accept | Migration applied by admin only via CLI or dashboard; not exposed to end users |
| T-01-06 | Information Disclosure | RLS SELECT policies | accept | All data is intentionally public (guild members read counter strategies); no PII stored in these tables |
</threat_model>
