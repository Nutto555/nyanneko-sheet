## Trust Boundaries

|----------|-------------|
| Admin UI -> Supabase | Template form data (name, members) flows from admin input to DB |
| App.tsx routes | New routes expose admin pages (protected by AdminAuthGate) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-07 | Tampering | TemplateForm input data | mitigate | Template creation/update flows through Zod schemas (createTemplateSchema, updateTemplateSchema) in strategies.ts service. Character IDs validated as UUIDs. Name fields rendered via JSX interpolation. |
| T-05-08 | Spoofing | Admin route accessible by URL | mitigate | AdminAuthGate wraps both AdminStrategies and AdminTemplates pages. Unauthenticated users see only the password prompt, never the admin UI. Server-side RLS enforces write protection regardless of client state. |
| T-05-09 | Information Disclosure | Template/strategy data visible to admin | accept | All counter strategy data is guild-visible by design. Admin seeing all templates and strategies (including inactive) is intentional for management purposes. |
</threat_model>
