## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, tight badge padding |
| sm | 8px | Compact element spacing, gap between nav items, card internal padding |
| md | 16px | Default element spacing, page horizontal padding (mobile), form field gaps |
| lg | 24px | Section padding, card body padding, gap between card groups |
| xl | 32px | Page vertical padding (py-8 = 32px), layout gaps between major sections |
| 2xl | 48px | Major section breaks (unused in this phase) |
| 3xl | 64px | Page-level spacing (unused in this phase) |

Exceptions: none

**Standardized page padding:** All pages use `px-4 sm:px-6 lg:px-8 py-8`. This replaces the current inconsistent mix of py-8, py-10, and py-16 across pages.

Source: RESEARCH.md Pattern 1 (page container standardization).

## Typography

| Role | Size | Weight | Line Height | Font Family |
|------|------|--------|-------------|-------------|
| Body | 14px (text-sm) | 400 (normal) | 1.5 | Sarabun |
| Label | 12px (text-xs) | 600 (semibold) | 1.5 | Sarabun |
| Heading | 24px (text-2xl) | 700 (bold) | 1.2 | Cinzel (--font-display) |
| Display | 30px (text-3xl) | 700 (bold) | 1.2 | Cinzel (--font-display) |

**Rules:**
- All page titles use Heading role with `style={{ fontFamily: 'var(--font-display)' }}`.
- Body text and descriptions use Body role (14px Sarabun).
- Badge labels, section headers in nav, and metadata timestamps use Label role.
- Display role is reserved for the Home page hero title only.

**Standardized page header pattern (extract PageHeader component):**
```
<h1> — Heading role (text-2xl font-bold text-white, font-display)
<p>  — Body role (text-sm text-slate-400 mt-2)
<hr> — Gold gradient divider (h-px, linear-gradient from --color-gold-dim to transparent)
```

Source: RESEARCH.md Pattern 2 (page header pattern), index.css font declarations.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #080b10 (--color-bg) | Page background, body background |
| Secondary (30%) | #0f1520 (--color-surface) / #131c2c (--color-surface-raised) | Cards, navbar background, dropdown menus, mobile menu |
| Accent (10%) | #7c3aed (--color-primary) | Active nav indicators, primary CTA buttons, selected states, focus rings, scrollbar thumb |
| Destructive | #ef4444 (--color-accent) | Delete buttons, destructive confirmation dialogs only |

**Additional semantic colors (informational, not part of 60/30/10):**
- Gold (#f0a030, --color-gold): Page header dividers, decorative borders, badge highlights for priority rank
- Primary-light (#a78bfa, --color-primary-light): Active nav text, hover states on interactive elements
- Secondary (#f59e0b, --color-secondary): Warning badges, condition indicators (must_not_have)
- Text default: #cbd5e1 (slate-300) for body text
- Text muted: #94a3b8 (slate-400/gray-400) for subtitles and metadata
- Text bright: #ffffff (white) for headings and emphasis

**Accent reserved for:** Active navigation link background (bg-primary/10), primary action buttons (Button variant="primary"), focus ring on inputs, selected character chips in multi-select, scrollbar thumb.

Source: index.css @theme declarations, Button.tsx variant system, Navbar.tsx active state classes.

## Navigation Contract

**Desktop nav order (left to right):**
```
Home | Counter | Attack | Defense (dropdown) | Database (dropdown) | Gear Guide | Admin
```

**Counter Lookup positioning:** Placed immediately after Home as the second item because it is the primary member-facing feature (core value proposition per REQUIREMENTS.md).

**Admin link:** Always visible in nav. Access is controlled by the password gate on the admin pages themselves, not by hiding the link.

**Mobile nav:** Follow existing slide-down pattern. Counter and Admin appear as top-level items (not nested in dropdowns).

Source: RESEARCH.md Pattern 3, Assumptions A2 and A3.

## Responsive Breakpoints

| Breakpoint | Width | Layout Behavior |
|------------|-------|-----------------|
| Default (mobile) | < 768px | Single column, mobile hamburger menu, full-width cards |
| md | >= 768px | Desktop nav visible, 2-column grids where applicable |
| sm | >= 640px | Increased horizontal padding (px-6) |
| lg | >= 1024px | Maximum horizontal padding (px-8), 3-4 column grids for character lists |

**Mobile-critical requirement (UI-03):** Guild members check strategies on phones during GvG battles. No horizontal scrolling at 320px viewport width. Character portraits must scale down gracefully. Strategy cards must be readable at mobile widths without truncation of critical information (counter team, conditions, priority rank).

**Character grid responsive pattern:**
- Mobile: `grid-cols-2`
- sm: `grid-cols-3`
- md: `grid-cols-4`
- lg: `grid-cols-5` or `grid-cols-6`

Source: REQUIREMENTS.md UI-03 success criterion, RESEARCH.md Pitfall 1.

## Anti-Patterns (Do Not)

1. Do NOT use `getImageUrl()` with raw `<img>` tags where a full Character object is available -- use CharacterPortrait instead.
2. Do NOT refactor UnitSlot to use CharacterPortrait -- UnitSlot operates on UnitSlotData (partial data) and has its own portrait rendering with stat badges. Leave as-is.
3. Do NOT use inline `style={{}}` for colors that are already available as Tailwind classes via `@theme` (e.g., use `bg-primary` not `style={{ background: 'var(--color-primary)' }}`).
4. Do NOT add new font weights beyond 400 and 700. Cinzel is loaded with 400/600/700; Sarabun with 300/400/500/600/700. This phase uses only 400 (body) and 700 (headings).
5. Do NOT change existing Tailwind `@theme` tokens. This phase enforces consistency with existing tokens, not new ones.

Source: RESEARCH.md Pitfall 3 (UnitSlot), Pitfall 4 (Tailwind 4 syntax), Anti-Patterns section.
