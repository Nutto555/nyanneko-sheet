1. `getEnemyTemplates(): Promise<EnemyDefenseTemplateWithMembers[]>` — select `*, enemy_defense_members(*, characters(*))` from `enemy_defense_templates`, ordered by `sort_order` asc. Returns `[]` if not configured.

2. `getEnemyTemplateBySlug(slug: string): Promise<EnemyDefenseTemplateWithMembers | null>` — same select but `.eq('slug', slug).single()`. Returns `null` if not configured.

3. `getCounterStrategies(templateId: string): Promise<CounterStrategyWithConditions[]>` — select `*, strategy_conditions(*, characters(*)), team_compositions(*)` from `counter_strategies` where `template_id = templateId` and `is_active = true`, ordered by `priority` asc. Returns `[]` if not configured.

4. `getAllCounterStrategies(templateId: string): Promise<CounterStrategyWithConditions[]>` — same as above but WITHOUT the `is_active` filter (for admin view). Returns `[]` if not configured.

**WRITE functions** (throw on error, matching admin.ts pattern; validate input with Zod schema `.parse()` before Supabase call):

5. `createEnemyTemplate(input: unknown): Promise<EnemyDefenseTemplate>` — parse with `createTemplateSchema`, insert, `.select().single()`, return data.

6. `updateEnemyTemplate(id: string, input: unknown): Promise<void>` — parse with `updateTemplateSchema`, update `.eq('id', id)`.

7. `deleteEnemyTemplate(id: string): Promise<void>` — delete `.eq('id', id)`. CASCADE handles members.

8. `createCounterStrategy(input: unknown): Promise<CounterStrategy>` — parse with `createStrategySchema`, insert, `.select().single()`, return data.

9. `updateCounterStrategy(id: string, input: unknown): Promise<void>` — parse with `updateStrategySchema`, update `.eq('id', id)`.

10. `deleteCounterStrategy(id: string): Promise<void>` — delete `.eq('id', id)`. CASCADE handles conditions.

11. `replaceStrategyConditions(strategyId: string, conditions: unknown): Promise<void>` — parse with `addConditionsSchema`. Delete all existing conditions for `strategyId`, then insert the new array. This is the append-only pattern from Phase 1.

12. `replaceTemplateMembers(templateId: string, members: Array<{ character_id: string; position: number }>): Promise<void>` — delete all existing members for `templateId`, then insert new array.

13. `reorderStrategies(templateId: string, orderedIds: string[]): Promise<void>` — for each id in `orderedIds`, update `priority` to the array index. Uses `Promise.all` with individual updates.

All write functions use `as never` cast on insert/update payloads to work around Supabase client type limitations, matching the existing admin.ts pattern.

Error handling: Read functions use `if (import.meta.env.DEV) console.error(...)` and return fallback. Write functions `throw new Error(error.message)`.

```typescript
import { z } from 'zod';

// ─── Enemy Defense Template schemas ─────────────────────────────

export const createTemplateSchema = z.object({
  name_en: z.string().min(1).max(200),
  name_th: z.string().max(200).nullable().optional(),
  slug: z.string().min(1).max(200),
  description: z.string().nullable().optional(),
  is_featured: z.boolean().optional(),
  sort_order: z.number().int().optional(),
});

export const updateTemplateSchema = z.object({
  name_en: z.string().min(1).max(200).optional(),
  name_th: z.string().max(200).nullable().optional(),
  slug: z.string().min(1).max(200).optional(),
  description: z.string().nullable().optional(),
  is_featured: z.boolean().optional(),
  sort_order: z.number().int().optional(),
});

// ─── Counter Strategy schemas ───────────────────────────────────

export const createStrategySchema = z.object({
  template_id: z.string().uuid(),
  counter_team_id: z.string().uuid().nullable().optional(),
  priority: z.number().int().min(0),
  condition_note: z.string().nullable().optional(),
  strategy_notes: z.string().nullable().optional(),
  is_active: z.boolean().optional(),
});

export const updateStrategySchema = z.object({
  template_id: z.string().uuid().optional(),
  counter_team_id: z.string().uuid().nullable().optional(),
  priority: z.number().int().min(0).optional(),
  condition_note: z.string().nullable().optional(),
  strategy_notes: z.string().nullable().optional(),
  is_active: z.boolean().optional(),
});

// ─── Strategy Conditions schema ─────────────────────────────────

export const addConditionsSchema = z.array(
  z.object({
    strategy_id: z.string().uuid(),
    character_id: z.string().uuid(),
    condition_type: z.enum(['must_have', 'must_not_have']),
  })
);

// ─── Inferred types for consumers ───────────────────────────────

export type CreateTemplateInput = z.infer<typeof createTemplateSchema>;
export type UpdateTemplateInput = z.infer<typeof updateTemplateSchema>;
export type CreateStrategyInput = z.infer<typeof createStrategySchema>;
export type UpdateStrategyInput = z.infer<typeof updateStrategySchema>;
export type AddConditionsInput = z.infer<typeof addConditionsSchema>;
```

Per D-07: These schemas cover write payloads only. Search inputs (character ID arrays) use plain TypeScript types — no Zod needed.

Field constraints match the SQL schema: `name_en` VARCHAR(200) NOT NULL maps to `z.string().min(1).max(200)`, `priority` INT NOT NULL CHECK >= 0 maps to `z.number().int().min(0)`, `condition_type` CHECK IN maps to `z.enum(...)`.
